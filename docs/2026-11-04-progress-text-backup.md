# 运行进度与文本备份补齐

用户反馈 `net-connector backup run --` 等待时不知道正在执行什么，并要求参考 Ruby 版本；随后明确不需要 `.raw` 旁车，保存正确的配置。

## 实现

参考 Ruby `lib/net/connector/progress.rb`、`netdisco/progress.rb` 和 `netdisco/cli/backup.rb`：在远端清单读取前显示阶段，计划展示总数、选中、跳过及并发，设备开始后显示连接/登录/采集状态，完成显示数量、耗时、受控失败原因和报告位置。TTY 一行刷新，重定向输出五秒心跳；心跳在返回或取消前唤醒并加入，不保留后台线程。`--verbose` 展示安全阶段事件，`--quiet` 关闭进度，JSON stdout 不混入进度。

新增 SessionEvent 只包含 Host/Name/Status，不携带命令文本、响应或凭据，独立于会话日志级别。显示 I/O 故障留在报告中，不重放命令或抹去已保存文件。

CLI 配置备份启用严格 TextOnly，只保存设备名称-IP.txt，不创建原文旁车；可验证 UTF-8/GBK/GB18030 转换，无法确认编码时失败，不新建或覆盖旧配置。厂商配置整理保持既有 Ruby 对齐策略，不用全局删首尾行改变配置。TFTP 保留厂商原生格式。旧 `.raw` 文件不在本轮删除。Go API 的保真备份默认值保留，调用方可显式使用 BackupOptions.TextOnly。

## 关键回归

- 首次清单访问前已显示阶段；`--` 结尾参数可执行。
- quiet 保持无进度、JSON 仍可解析。
- 连接和采集事件无需创建回显日志，事件不包含原始数据。
- 失败命令/脚本不会显示“响应已接收/执行完成”；跳过、待核实与失败分开计数。
- 拓扑应用阶段重新计算实际任务规模，不把发现与应用累加成超过总数。
- TTY 心跳原地刷新；停止幂等、取消加入、首次输出错误保持。
- TextOnly 正常中文、多字节分包、旧编码、不可解码、未变化和持久化失败边界。
