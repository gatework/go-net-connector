# 两库联动重构与接口收敛

## 授权与基线

用户批准完整联动方案：允许直接收敛 Go API 并迁移本地消费者，不保留兼容包装；本地重构与隔离源码配对验收，不提交、推送或发布。Go 最低版本仍为 1.26。保留此前备份编码、原文旁车和中文 CLI 的全部未提交工作。

## 设计与验收

- go-expect 拥有不可变 Pattern、字节匹配、I/O 与脱敏算法；新增 Line、IsZero、ValidateText，保留 per-wait 游标和公开脱敏输出的独立所有权。
- connector 明确 RawPrompt 与检查错误的 Prompt，Response 为唯一响应访问入口。配置使用 Config，普通命令使用 JoinedOutput；不混用 wire 字节与可见文本。
- 修复采集异常退出、全部命令跳过、版本选项离线性、上传原因树和拓扑完成回执保留。备份双文件状态由回执查询方法统一表达。
- 收敛重复发送、响应累积、原文保存、日志作用域和批次报告流程；预先编译协议、glob 与有限正则目录，不引入通用执行框架或全局对象池。
- 性能先核对输出/错误一致，再对受影响路径与对照做十组交错样本；相关控制指标显著退化超过 5% 则撤销该性能优化。

## 依赖边界

正式 go.mod 仍固定已发布 go-expect v0.1.2；本轮新增 API 的集成依靠脚本在临时副本合入候选源并重写导入前缀。正式模块不添加 replace/go.work，不伪造未发布版本。候选源通过不表示旧固定依赖可以构建新增接口；正式版本采纳需以后单独授权发布与固定依赖。

## 尚未完成的消费者契约

Wireless 已机械迁移 Pattern、Response 与 RawPrompt；生产逻辑保留旧借用会话接口，尚不能编译。不能通过吞掉回调错误来迁移：当前 execute 对任何错误都会关闭会话。需要明确的新执行策略只对完整响应、已验证目标提示符、纯设备拒绝且上下文有效的情况保留连接；编码、回调、取消、传输失败均应退休。还需要受作用域约束的主动退休和独立清理错误证据，且借用操作不得自动重连。已有 Attempts/OnReceipt 可提供部分证据，无需重建部分输出接口；重入断言应迁移到当前观察机制。以上新生命周期设计尚未实施，不增加兼容别名掩盖差异。

VXLAN CLI 使用的 resources.Prepare 资源预检已被上游删除，需明确新的资源预算归属后迁移；未删除预检绕过此问题。消费者正式 go.mod 保持不变，临时工作区验证不算已发布依赖采纳。

GB 提示符边界复查补充了严格采集与备份两条回归：可见输出边界使用检查错误后的 Response.Prompt，备份提示符独立严格解码。最终 Go 1.27.1 全量配对通过。并行运行的 Go 1.26 复验仅归档 SSH 子进程清理测试发生 5 秒超时，已保存失败日志；需在基准结束后串行复验，不修改测试超时掩盖问题。
