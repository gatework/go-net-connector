# v0.8.0

本版本统一平台术语，新增提交模型平台下发、设备事实采集与本地静态清单。**不保留兼容层**，包含配置、CLI、报告格式与 Go API 的破坏性变更。

- **术语统一（破坏性）**：`vendors/dialect` 更名为 `platform`，家族类型为 `Platform`；`fleet.Record.Vendor`、`Mapping.Connector` 改为 `Platform`，`Record.BackupFilename(style)` 改为 `Record.Filename()`。配置键 `include_vendors`/`exclude_vendors`/`vendor_overrides`/`ssh.vendor_protocols`/`backup.limit_per_vendor` 及对应 `NC_*VENDOR*` 变量改为 `*platform*`，`--vendor`/`--exclude-vendor` 改为 `--platform`/`--exclude-platform`，设备规则使用 `platform`；旧名不再识别。报告 schema 升为 v4，拓扑计划记录 `platform`。
- **平台模型收敛（破坏性）**：能力数据类型归属消费方（`topology.Neighbor`、`transfer.TFTPOptions`、`transfer.TFTPEvidence` 等）；`transfer.TFTPPolicy` 精简为六个方法，源文件发现为可选 `transfer.SourceFileResolver`；`fleet.PlanOptions` 以注入的 `Admit`/`ReuseDestination` 取代 `Mode`/`AllowFixedNameReuse`；`LoginState.HAState` 改为 `Labels`/`Device.LoginLabel(name)`，已特权登录提示由 `Terminal.PrivilegedPrompt` 声明。
- **下发前后快照**：`deploy run` 在变更前后采集配置并写出 unified diff（`before/`、`diff/`、报告 `artifacts.change`）；`--no-snapshot` 关闭，`--backup` 移除。
- **候选配置下发**：Juniper Junos 与 Palo Alto PAN-OS 支持 `connector.Committer`/`Operation.Commit`，Junos 支持 `deploy run --commit-confirm <分钟>`；仅凭设备的正向提交证据认定提交成功，报告记录 `artifacts.commit`。
- **设备事实采集**：新增 `netman facts plan|run` 与 `facts` 包，只读采集 Cisco IOS/NX-OS、H3C、Huawei、Juniper、Fortinet 的型号、序列号、软件版本与运行时间，并与清单比对（`artifacts.facts.mismatches`）。
- **本地静态清单**：`inventory.source: file` 配合 `inventory.file`（YAML `devices:` 列表或 CSV），由新包 `inventoryfile` 读取；地址无效、重复或字段未知时拒绝整份文件。
- **其他**：新增 `netman platform list`（文本或 `--json`）、`connector.CanCollectConfig`/`CanSave`、类型化 `batchreport.Status`/`Outcome`、`connector.LogLevel`、`connector.LoginCommitter` 与 `Terminal.Clone`；删除 v0.6.0 已移除配置键的拒绝表、API 迁移指南与下游源码探测脚本。

依赖保持正式 go-expect v0.6.0。发行文件来自同一提交成功 CI 的不可变制品，覆盖 Linux/macOS × amd64/arm64。提交下发与事实采集模板依据厂商公开命令参考编写，仅以模拟设备验证，不代表真实网络设备验收。
