# v0.2.0

本版本改进设备操作、批次执行与归档事务的资源所有权和失败证据，并统一配置入口。包含不兼容的 Go API、归档协议和配置格式变更；升级前请阅读 API 与配置迁移说明（见对应版本标签下的 docs/api-migration.md）。

- 归档协议升级为 v2，准备、上传、核验和清理分别受阶段期限约束。服务器证明、本地持久化和清理确认分别保留，失败时仍可检查已完成的成果。
- 统一自动发现和初始化的配置文件为平铺的 `net-connector.yml`，移除 `backup.yml`、`topology.yml` 自动发现及旧嵌套格式。凭据继续使用 `.env` 或环境变量；现有文件不会自动改写或删除。
- 新增 `netman config defaults [--for backup|tftp|topology] [--json]`，直接打印内置默认值，不读取本地配置、环境覆盖、凭据或清单。默认值、worker 路径与归档超时复用同一来源。
- 修复 TFTP 批次产物导出，支持批次目录整体移动，拒绝中间目录及文件符号链接。
- 重整工作流和厂商模块，强化设备生命周期、传输和存储回执；清单缓存按非敏感账户身份隔离，避免不同主体复用缓存。
- 固定使用正式发布的 `go-expect v0.4.0`，不使用本地依赖替换。

## 升级要求

1. 客户端与远端 `tftp-archive` worker 必须同步升级；v2 不兼容旧 worker，预检会在设备命令执行前拒绝旧版本。
2. 将原用途配置及 `common` 等容器中的实际设置合并到一个平铺 `net-connector.yml`。只保留站点覆盖值，避免复制整份默认参数；TFTP 默认成功策略为 `verified`。
3. Go 调用方按迁移说明适配归档 `Result`、独立回执及其余公开 API 变更。

发行包包含 Linux/macOS 的 amd64/arm64 二进制、对应提交源码、版本及提交身份、第三方许可和 SHA256 校验和。验证证据来自离线测试、本地 worker 与 GitHub CI，不代表实机或生产部署验证。
