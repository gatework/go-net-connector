# v0.6.0

本版本新增面向运维的批量脚本下发，并统一枚举、厂商声明与计划预览的数据结构。包含一项破坏性配置变更。

- 新增 `netman push plan|run`：`--script` 适用于所有平台，`--script-for 平台=文件` 按规范平台键覆盖。全部脚本在读取配置、凭据和清单之前校验，拒绝 NUL、控制字符和非 UTF-8 并报告行号；`plan` 不连接设备。每台设备在一次操作租约内顺序执行，设备拒绝或结果不确定即停止该设备，不重试、不重放。`--save` 仅以平台正向保存回执为成功，未声明保存脚本的平台在规划阶段跳过；`--stop-after-failures` 只阻止尚未开始的设备。`report.json` 区分已接受命令数与包含失败命令的写入尝试。
- **破坏性变更**：删除 `tftp.h3c_source_file`、`tftp.h3c_wireless_source_file`、`tftp.huawei_source_file` 及对应环境变量，统一使用 `tftp.source_files.<平台>`。旧键出现时明确报错并给出替代字段，不会静默回退。
- 成功策略、输出布局、清单缓存模式、名称/型号匹配方式与配置字段类型各有唯一定义，配置校验、CLI 校验、批次报告、展示与 shell 补全共用；字符串取值不变。`netdisco.FetchOptions.Mode` 与 `Cache.Fetch` 改用 `netdisco.CacheMode`。
- 厂商构造函数返回导出类型（如 `h3c.Dialect`、`cisco.IOSDialect`）；只读拓扑能力由 `driver.TopologyReader` 组合，H3C/Huawei 共享命令错误与确认规则。TFTP 参数错误仍匹配 `connector.ErrInvalid`，并标明字段名而不回显取值。
- 计划预览改为类型化 `workflow.PlanView`，JSON 输出与先前逐字节一致。启用 modernize、errorlint 与 revive 部分规则，采用 Go 1.26 标准库新写法。

依赖升级为正式 Expect v0.5.0（源码提交 `33bf675`，诊断字段重命名不影响本模块 API）。迁移步骤见 [API 迁移](../api-migration.md)。发行包使用同提交成功 CI 的不可变制品，覆盖 Linux/macOS × amd64/arm64；push 仅以模拟设备验证，本地与 CI 测试不代表真实设备或生产部署验收。
