# v0.7.0

本版本以业务对象重组模块：单设备阶段流水线、统一批次报告与平台驱动模型，并补齐运维能力。**不保留兼容层**，包含 CLI、报告格式与 Go API 的破坏性变更。

- **单设备阶段流水线**：每台设备一次会话内依次执行 认证 → 业务阶段（执行脚本 → 保存 → 备份 等），任一阶段失败即拦截后续阶段；失败设备不重试、不重放写入。报告逐阶段记录状态、耗时与诊断（`failed_stage`），认证失败单独记为 authenticate 阶段。
- **统一报告 schema v3**：备份、TFTP、远程导出、下发、只读采集与拓扑共用 `report.json`（取代 `summary.json`/`summary.txt`）：统一 `status`、操作专属 `outcome`、`stages[]`、`diagnostic{code,phase}` 与 `artifacts` 证据；诊断不含 Ruby 类型名、设备回显或密钥。`plan` 命令输出同格式的计划报告，不做 I/O。
- **平台即驱动**：`connector.Profile` 拆为 `Terminal`（终端语法）与 `Driver`（配置采集、保存确认及可选钩子）；`dialect.Platform` 内嵌 `connector.Driver` 与 `MatchInventory`。各厂商能力在编译期校验。
- **CLI**：`netman push` 更名 `netman deploy`（新增 `--backup`）；`backup run`/`backup tftp` 支持 `--save`；新增 `netman exec`（平台声明的只读命令，拒绝重定向类管道）、`netman backup remote`（Juniper 原生 SCP/FTP 导出）、`netman backup diff`（两批次 unified diff，退出码 0/1/2）。
- **连接**：`ssh.jump_host` 经 `ssh -J` 走跳板机（与 Telnet 互斥）；`ssh.connect_retries`（默认 1）仅在登录提示前的连接被拒/无路由/超时时重试，认证失败从不重试。"无路由/连接超时"不再误报为认证失败。
- **清理**：删除不可达 API、旧缓存身份路径、模板索引、`fleet.Run/Report`、Ruby 诊断映射与历史文档；`config.Load(ctx, …)` 取代兼容包装。

依赖保持正式 Expect v0.5.0。go-vxlan、go-wireless（v0.4.0）与 Firemon 适配器（v0.2.0）升级时需按 API 迁移（见对应版本标签下的 docs/api-migration.md） 调整。发行包使用同提交成功 CI 的不可变制品，覆盖 Linux/macOS × amd64/arm64；新能力仅以模拟设备验证，不代表真实设备、跳板机或远端服务器验收。
