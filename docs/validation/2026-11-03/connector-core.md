# Connector 核心改动与验证

本轮保留既有编码/中文 CLI 未提交工作；未提交、推送、发布，也未连接真实设备。正式依赖仍固定已发布版本，新接口只在隔离副本中与候选 go-expect 源码配对，不添加 replace/go.work。

## 行为与 API

- Profile、Interaction 和 Command 的会话边界使用不可变 `expect.Pattern`；配置提示符使用 `expect.Line`。认证/命令错误仍是内容正则。
- `Response` 是响应访问入口；`Output/Rendered/Prompt` 检查转换错误，`Raw/RawPrompt` 保留原字节。普通结果使用 `JoinedOutput`，配置结果使用 `Config`。
- 设备的 `RawPrompt` 只保存最终 wire 提示符行；完整匹配仍在响应中保留。Huawei 的权限确认文本不再混入下次精确边界。Fortinet、Juniper 直接复制不可变 Pattern。
- 配置采集共享 panic/Goexit/普通失败的会话回收边界；全部命令被跳过时返回不完整配置，不访问空步骤。
- 响应分段按 4KiB 合并细碎片段，普通短响应直接取得 builder 的不可变视图，大响应仅做一次精确拼接。首次排除分页符后才分离 raw/body。
- 旧文件指纹以固定缓冲读取而不保留正文；原文以不可变响应段分块保存。双文件完成/保存证据由回执查询方法统一表达，保存后的错误分类共用同一路径。
- 编码告警在转换时记录总量和前 64 个字节位置，持久化阶段复用元数据；相邻响应之间没有换行时，位置按真实拼接原文计算。
- 日志 metadata 事件保留已编译脱敏规则；真正的秘密/作用域切换仍刷新边界。保存验证的有限正则提前编译。

## 回归证据

`core-tests.log` 是最终 connector/vendors/storage/textcodec 的隔离源码配对 race、shuffle 和 vet 通过记录。完整应用、Go 1.26 及跨平台记录由同目录其他验证文件提供。

新增测试覆盖采集策略工厂/Finish 的 panic/Goexit、空步骤、响应碎片元数据上界、不可变快照、分块文本持久化、告警计数/截断及跨响应位置。既有重放、错误树、秘密、关闭、回执与编码测试一并运行。

`core-warning-red.log` 记录跨响应告警位置原先误计为第二行；修复后按原文仍在第一行。`core-gb-prompt-red.log` 记录 GBK 提示符的严格采集及备份原先分别失败；修复使用已检查的可见 Prompt 处理文本边界，wire 匹配仍使用原字节。

## 性能方法与边界

工具链为 Go 1.27.1、darwin/arm64、Apple M5。主基准为十组交错的 before/after，各 100ms；顺序逐组反转，测试与编译结束后重新清空采样。baseline 为实施前保留的 `/tmp/go-net-connector-review.test` 二进制，没有对应完整源码快照，不声称它是 HEAD 或可重建的基线。候选与基线二进制哈希、候选生产源码哈希见 `core-benchmark-manifest.json`。

完整联合改动增加了短命令的临时字节数；移除 collector 后仍有这一差异，应归入联合 API/执行实现变化，尚未归因到单一函数，不能把该差异归因于响应分段优化。为此另在同一候选 API 下，仅把 collector 替换为原 builder 策略，进行十组交错日志对照：

| 对照 | ns/op 变化 | B/op 变化 | allocs/op |
| --- | ---: | ---: | ---: |
| 无日志 | +0.09% | +1.46% | 70 → 70 |
| INFO | -1.79% | +1.04% | 123 → 123 |
| DEBUG | -1.60% | +0.28% | 210 → 210 |

上述独立控制均在 5% 范围内；原始数据在 `core-collector-control.txt` 和 `core-collector-after.txt`。这里报告中位数，不给出未经统计检验的显著性声明。

存储补充基准在同一当前实现内比较旧保留正文/新仅指纹以及旧整段字节/新流式文本，8MiB 输入，各十次单轮，原始记录见 `core-storage-bench.txt`：

| 路径 | 旧 B/op | 新 B/op | 旧/新耗时中位数 |
| --- | ---: | ---: | ---: |
| 指纹 Read → Inspect | 17,064,272 | 33,520 | 3.93ms / 3.29ms |
| 文本 Bytes → Stream | 8,394,000 | 38,168 | 8.86ms / 10.29ms |

存储单轮文件系统结果不是稳定延迟对照：分块文本显著降低临时内存，但增加写调用，观察到耗时增加；不能据此声称写入提速。主命令路径的完整结果由最终十组交错数据补充。
