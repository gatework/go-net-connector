# 实施裁定记录

以下按实施账本中的顺序列出本次采用的边界及判断错误时的代价。

1. 未获得提交或发布授权，使用未提交文件差分和冻结快照作为审查依据。代价：尚无 Git 提交历史，复审材料需另行保留。
2. 新项目保留在 `feat/ruby-parity`，expect 兼容改动放入隔离副本，保留原工作区。代价：正式消费需要先重建工作区，发布前还需发布兼容的 expect 版本。
3. 命令回执只在提示符匹配且拒绝检查通过后产生；流式日志在此之前失败，不推断命令完成。代价：设备实际可能已经完成，但客户端证据不足，结果仍为不确定；不会自动重放。
4. Go 正则分页匹配消耗的换行在 connector 适配层还原，保留原始响应和正文分隔。代价：若厂商分页规则变化，需要同步更新适配及夹具。
5. dotenv 展开和调用方配置树采用资源上限及复制，配置输入允许可读符号链接；备份、缓存的禁止符号链接规则不套用到配置输入。代价：过大配置会被明确拒绝；配置来源自身仍需可信。
6. 交互初始化区分“允许创建文件”和“自定义内容”；拒绝自定义仍按 Ruby 行为写入默认内容，`--init` 直接授权创建缺失文件。代价：调用者需理解这两个不同问题；已有文件不被覆盖。
7. 因没有提交历史，保留 `.superpowers/sdd/implementation-plan/` 下的审查证据。代价：本地增加审查材料，但避免清理时丢失唯一记录。
8. 交付冻结的 expect 源码归档及兼容补丁，不追入冻结后原工作区的并行修改。代价：当前依赖仍是本地占位，正式发布需要单独处理依赖版本。
9. 将终审明确未评价的事项保留为证据边界：生产设备及固件、真实 SSH 密码登录和管理员安装、发布和远端 CI、原 expect 的并行修改、amd64 原生运行、真实网络吞吐和单设备生产内存、依赖 CVE 审计。代价：这些结果不能由本次本地实现与测试推断，实际部署或发布前仍需针对所需环境验证。
10. 错误分类以冻结 Ruby 的具体抛出位置为准：无效 UTF-8 为 `ParsingError / invalid_output_encoding / parse`，配置正文不完整为 `DeviceError / incomplete_configuration / collect`，缺少配置策略与之区分。代价：若基线选择错误，下游错误分组会不同；对应调用链回归测试固定这些具体边界。
11. 按 Ruby 本地备份的回执条件区分持久化错误：提交前保留存储写入错误，已提交文件的后续失败才使用 `BackupPersistenceError`，两者均保留受控底层错误类型。代价：分类错误会混淆“未保存”和“已保存但持久化未确认”；测试分别检查这两类状态及回执。
12. 用户随后明确授权创建私有 `gatework/go-net-connector`、提交推送并发布首版，因此早期的未提交边界已被这项授权更新。正式依赖发布涉及另一个当前公开的 `go-expect` 仓库，仍等待范围确认。代价：在其兼容版本可用前保留占位依赖，发布流水线明确拒绝生成正式产物。
