# 设计约束

本文件是现行设计约束，取代已删除的 `implementation-plan.md` 与 `decisions.md`（见 Git 历史）。模块不再以 Ruby net-connector 为对齐基线：报告、诊断与配置格式以本仓库定义为准，设备侧行为由本仓库测试固定。

## 范围

单模块 `github.com/gatework/go-net-connector`，Go ≥ 1.26，Linux/macOS amd64/arm64。通过 go-expect 与系统 SSH/Telnet 客户端驱动网络设备，提供登录、配置采集与备份、TFTP/原生远程备份、邻居发现与接口描述修正、批量脚本下发（含变更前后快照与差异、候选配置提交）、只读命令采集和设备事实采集；清单来自 Netdisco 或本地文件。依赖使用固定的正式版本，`GOWORK=off` 解析，不使用 `replace`。

## 分层与所有权

- `connector`：一台设备的会话生命周期、命令/脚本执行、操作租约、回执与本地备份。`Device` 拥有会话与租约；transport 拥有子进程；go-expect 拥有流匹配与 I/O。
- `platform`：`Platform`、`Registry`、清单身份与诊断错误的叶子契约；能力接口及其数据类型由消费包（`topology`、`transfer`、`facts`、`connector`）定义。
- `vendors`：静态内建平台目录。每个 family 包提供平台对象（终端规则与可选能力）；能力接口由消费包定义，Registry 只做身份识别与键查找，不做运行时插件。
- `fleet`：清单到批次计划、统一执行与报告。
- `topology`、`transfer`、`archive`：各自业务能力；不包含厂商命令分支。
- `internal/*`：组合根（bootstrap）、CLI、展示和进度。业务包不得依赖 CLI 或组合根（`scripts/check-architecture.py` 校验）。
- 新 API 使用 `context`、有界资源所有权和显式依赖注入；不使用全局服务定位器。

## 设备操作规则

1. 连接或发送前校验完整脚本；不确定结果之后绝不重放设备写入，失败设备不自动重试命令。
2. 命令回执只在提示符匹配且拒绝规则检查通过后产生；仅出现提示符不代表设备接受或已持久化。
3. 保存成功必须由平台的正向保存回执确认；没有回执即为未确认。候选配置的提交同理：只有平台的正向提交回执才算提交成功，共享候选配置中的残留变更不自动回退。
4. 失败的尝试证据（Attempt）与已接受步骤（Step）分开保留；后续日志、回调或持久化失败不得抹去已完成的步骤和存储提交回执。
5. `Device.Close` 为终止操作，取消进行中的操作且不等待用户回调；失败的会话需显式 `Connect` 后才能再次执行。
6. 原始响应只能显式访问；诊断格式不得包含密钥或响应正文。
7. 分页匹配消耗的分隔符在适配层还原，保留原始响应与正文分隔。

## 配置与存储

- 配置输入有字节、节点与深度上限，允许可读符号链接；备份与缓存路径禁止符号链接。
- 初始化区分"允许创建文件"与"自定义内容"，从不覆盖已有文件。
- 本地备份区分"提交前写入失败"与"已提交但持久化未确认"，两者都保留受控的底层错误。

## 证据边界

本地与 CI 测试不代表生产设备、固件、真实 SSH 密码登录、远端归档部署或网络性能的验收；这些需在相应环境另行验证并记录到 `progress.md`。提交、推送、发布与部署均需用户明确授权。
